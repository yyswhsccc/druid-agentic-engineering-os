The product is the framework

Druid is not a one-off AI prompt. It is an engineering loop: scan a live repository, classify risks, write the smallest useful patch, add regression tests, open the PR, track CI/review, and update strategy from what gets merged, rejected, superseded, or rewarded.

Finds risk-shaped work

Looks for places where state, money, security, review policy, or operational defaults can fail in ways maintainers care about.

Ships bounded fixes

Turns the finding into a narrow patch with tests, a reviewable PR body, and explicit risk boundaries.

Maintains the review loop

Watches CI, maintainer feedback, stale work, superseded work, and merge/close signals instead of treating PR creation as the finish line.

How Druid finds the work

The agent looks for bug shapes that usually survive ordinary TODO scanning: value movement, state transitions, trust boundaries, concurrency, and production configuration edges.

1 / Scan

Map risky boundaries

Starts from routes, CLI entry points, payout handlers, bridge flows, ledger writes, browser dashboards, env parsing, and recently changed code.

2 / Prove

Filter for real impact

Keeps candidates only when the failure can affect money, state integrity, security exposure, reliability, review policy, or user-visible accounting.

3 / Ship

Cut to a reviewable PR

Checks collision risk, writes the smallest patch, adds regression tests, explains the boundary, then tracks CI and maintainer feedback.

Where Druid finds value

The strongest signal is not raw PR count. It is the ability to scan a complex system and repeatedly find reviewable risk surfaces across independent parts of the codebase.

Money path

Payout exact-once and terminal status

What it finds: repeated claim paths, missing status rows, terminal states that can be overwritten, and precision edges.

Why fix: these bugs can corrupt balances, confuse payout state, or make accounting unreliable.

Bridge

Terminal-state integrity

What it finds: bridge void/refund races, stale operator-only flows, malformed config defaults, and missing state visibility.

Why fix: bridge flows are trust boundaries; ambiguous terminal states create payout and operator risk.

Ledger

UTXO and transaction atomicity

What it finds: nonce races, ownership drift, value conservation edges, invalid rollback paths, and mempool inconsistencies.

Why fix: transaction systems need invariants that survive concurrency, retries, and bad payloads.

Security boundary

Browser, CORS, and public/admin exposure

What it finds: dashboard escaping gaps, permissive Socket.IO origins, public lock-status leaks, and legacy routes missing parity gates.

Why fix: small UI/API boundary bugs become real attack surface when they expose state or accept hostile input.

Governance

Proposal and fee accounting

What it finds: rejected proposal charge ordering, vote pagination drift, and hidden accounting truncation.

Why fix: governance systems need state changes and fees to match user-visible outcomes.

Operations

Reliability hardening

What it finds: malformed numeric env defaults, unsafe limits, payload compatibility breaks, and service startup footguns.

Why fix: production systems fail at the edges; hardening those edges lowers recurring maintenance cost.

How the loop maintains itself

Autonomous, not reckless

Low-touch routine work, human-gated risk.

Druid currently uses bounty and reward signals as one training environment, but the framework generalizes to any repository with issues, tests, CI, and review feedback.

Routine work can run low-touch. High-risk decisions, policy changes, and final approvals stay human-in-the-loop.

Discovery

Scans issue activity, recent maintainer behavior, changed code paths, public endpoints, state machines, and test gaps.

Prioritization

Ranks tasks by risk surface, bounty/reward fit, proof quality, review friction, collision risk, and expected maintenance cost.

Maintenance

Tracks CI, review comments, requested changes, superseding PRs, dirty branches, stale work, and whether a maintenance note helps or just adds noise.
